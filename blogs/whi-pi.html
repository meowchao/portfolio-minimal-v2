headless pi on a captive portal network

April 12, 2026
This took a little longer to figure out than i expected for some reasons (maybe lack of motivation idk).

I live in a hostel. The hostel provides WiFi but it's behind a captive portal meaning you connect to the network but there's no internet until you open a browser, go to a login page, and enter your credentials.

The problem: I have a Raspberry Pi with no screen, no keyboard, no mouse. A headless setup. i know pretty cool i can't open a browser on it. So how do one authenticate a captive portal on a machine with no GUI?

This is what I figured out.

the setup

Before anything, I needed a way to SSH into the Pi without being on the same network. My solutio phone hotspot as a temporary bridge. I connected the Pi to my phone's hotspot, connected my laptop to the same hotspot, and SSHed in. easy

But this only works when I'm physically near my phone and on the same hotspot. Not ideal So installed Tailscale on both the Pi and my laptop. thanks ayush for the idea (aysuh is my friend :])

installing tailscale

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

Running tailscale up prints an authentication URL. Open it on any device, log in, and the Pi joins your Tailscale network permanently. Now you get a 100.x.x.x address that works from anywhere in the world regardless of what network the Pi is on. 

tailscale ip

tailscale gives you the ip save that or its also available in the tailscale dashboard 

ssh spikey@raspberrypi

figuring out the captive portal

A captive portal is just a web form. When you connect to the WiFi and open a browser, the network intercepts your request and redirects you to a login page. You fill in credentials, hit submit, and the form POSTs your data to an authentication server. Once authenticated, your MAC address is whitelisted and traffic flows freely.

The key insight: a browser isn't special here. Any HTTP client can do the same thing. Including curl.

finding the form details

Connect your laptop or phone to the hostel WiFi, let the captive portal page load, and inspect the HTML source. You need three things:

  • The form's action attribute — this is where the POST goes
  • The name attribute of the username input field
  • The name attribute of the password input field
  • Any hidden input fields — these are often required for authentication

In my case, the portal was running on phc.prontonetworks.com and the form looked like this: 

<form action="/cgi-bin/authlogin?URI=http://detectportal.firefox.com/canonical.html" method="POST">
  <input id="userId" type="text" name="userId">
  <input id="password" type="password" name="password">
  <input type="hidden" name="serviceName" value="ProntoAuthentication">
  <button type="submit">Login</button>
</form>

Three fields: userId, password, and a hidden field serviceName with value ProntoAuthentication. That hidden field is easy to miss if you only look at the visible inputs always check for hidden fields.

replicating the login with curl

Once you have the form details, replicating the login is straightforward: 

curl -v -X POST "http://phc.prontonetworks.com/cgi-bin/authlogin?URI=http://detectportal.firefox.com/canonical.html" \
  --data "userId=YOUR_USERNAME&password=YOUR_PASSWORD&serviceName=ProntoAuthentication" \
  -L

The flags:

  • -X POST — send a POST request, same as submitting the form
  • --data — the form fields as key=value pairs joined by &
  • -L — follow redirects, portals redirect on successful login
  • -v — verbose output so you can see what's happening

A successful response returns HTTP 200 with an "Access Granted" page in the body. Test it on your laptop first before putting it on the Pi. After running it, try ping google.com — if you get replies, it worked.

automating it on boot

the script

nano ~/captive_login.sh
#!/bin/bash
sleep 20
curl -X POST "http://phc.prontonetworks.com/cgi-bin/authlogin?URI=http://detectportal.firefox.com/canonical.html" \
  --data "userId=YOUR_USERNAME&password=YOUR_PASSWORD&serviceName=ProntoAuthentication" \
  -L

The sleep 20 is important. On boot, NetworkManager takes several seconds to associate with the WiFi network and get an IP. If curl runs immediately, there's no network yet and the login fails. 20 seconds gives enough margin. 

chmod +x ~/captive_login.sh

scheduling with cron

cron is Linux's built-in task scheduler. i love linux more now crontab -e opens your personal schedule file. Add this line: 

@reboot /home/spikey/captive_login.sh

@reboot is a special cron directive that runs the command once every time the system boots. Make sure the path matches your actual home directory — if your username isn't pi, update it accordingly.

network fallback with networkmanager

This was the part where i almost lost my remote access. If the Pi connects to the hostel WiFi but the captive portal login fails for any reason, there's no internet, Tailscale can't reach its coordination server, and you're locked out with no way to SSH in remotely.

The fix: configure a fallback network. My Pi runs Debian Trixie which uses NetworkManager i used nmcli to configure my network priorities i had no idea you can do this agin i love linux 

# Add hostel WiFi (open network, no password)
sudo nmcli dev wifi connect "A-VIT" ifname wlan0

# Add phone hotspot as fallback
sudo nmcli dev wifi connect "YourHotspot" password "yourpassword" ifname wlan0

# Set priorities — higher number = preferred
sudo nmcli connection modify "A-VIT" connection.autoconnect-priority 10
sudo nmcli connection modify "YourHotspot" connection.autoconnect-priority 5

Now on boot the Pi tries the hostel WiFi first. If that fails, it falls back to the hotspot. Either way Tailscale comes up and you can SSH in to debug.

Captive portals are dumb like me. They're just HTML forms, automating them is a straightforward curl command and a cron job. The harder problem is making sure you never lose remote access in the process which i almost lost which comes down to always having a fallback network configured before making changes.

The Pi now boots, authenticates itself, and comes online without any manual intervention. I can SSH into it from anywhere via Tailscale. No screen, no keyboard, no mouse needed. YAY !!
